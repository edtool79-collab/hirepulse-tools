What it does

Temporary Email Inbox & OTP API for AI Agents

Creates time-limited, private disposable inbound email inboxes and extracts numeric one-time passwords (OTPs) and their provenance from received SMTP messages. The Actor provisions a random private email address and associated secret access credential for the creating account, receives real inbound email, parses plain-text and HTML message content for 4–8 digit verification codes located near verification or OTP labels (including supported non‑Latin labels), and returns extracted numeric candidates with provenance metadata such as a message identifier, receipt/expiry timestamps, extraction method, source indicator, and sender verification flag. Technical capabilities include inbox lifecycle management (provision, list message metadata, retrieve code candidates, revoke/delete inbox), conservative OTP parsing tuned for verification/security labels, per-inbox message metadata retention, and time-limited ephemeral inbox allocation tied to the creator’s account.

Use cases

  • Authorized QA of email verification and OTP flows for applications and staging environments
  • Automated testing and validation of registration and login verification processes
  • Integration with workflow automation tools (n8n, Make) and AI agents to obtain test OTPs
  • End-to-end testing of systems that send numeric verification codes via email
  • Inspecting message metadata and selecting specific messages for targeted code extraction

Test an email verification flow in three runs

For QA engineers and automation developers testing an application they own or are authorized to test. Keep the inbox ID and private capability from the first run and use the same Apify account for all steps.

1. Create a ten-minute inbox

{"action":"create","ttl_seconds":600}

Create a test inbox in Apify

Set the run's maximum charge to at least $0.011. Copy the returned address into your application's email test. Send the verification email using your application's usual email provider. The Actor receives email and returns promptly after allocating the inbox.

2. Retrieve the code after your application sends its email

{"action":"get_code","inbox_id":"REPLACE_WITH_INBOX_ID","capability":"REPLACE_WITH_PRIVATE_CAPABILITY","wait_seconds":30}

This run costs $0.001 and waits up to 30 seconds. A pending result means no retained message has arrived yet. no_code means no supported numeric code was found. ambiguous means multiple candidates were found. A code result returns a numeric candidate and provenance. Check it against the code your test application expects. Each additional Actor run incurs another start charge.

3. Delete the inbox when your test finishes

{"action":"delete","inbox_id":"REPLACE_WITH_INBOX_ID","capability":"REPLACE_WITH_PRIVATE_CAPABILITY"}

Deletion revokes further reads of the live inbox. Previous Apify run outputs follow Apify storage retention. Keep capabilities and OTPs in private workflow state and restricted Apify storage.
